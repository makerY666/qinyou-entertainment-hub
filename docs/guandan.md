# 四人掼蛋

在大厅「开一桌」中选择「掼蛋 · 四人组队」。四个座位准备好后开局；可由四位亲友联机，也可由电脑补位。与麻将、斗地主共用身份、邀请、WebSocket、存档、重连托管、房主管理、账目及历史回放。

## 本项目的亲友规则

两副牌共108张，每人27张，两副牌的重复牌面仍有独立编号（0–107）。1、3号座为一队，2、4号座为二队。从2打起，级牌高于A、低于小王。红桃级牌为逢人配，可替代除王以外的牌，单独出时仍为级牌。

支持单张、对子（包括同种王的对子）、三张、三带两、五张顺子、三连对、两连三张（钢板）、四至十张同点数炸弹、五张同花顺、四大天王。连续牌型按自然点数排序，级牌在连续牌型中不额外变大；A可在最前或最后，不循环。顺子固定五张、三连对固定六张、钢板固定六张。四大天王由两张小王和两张大王组成；配牌不能充当王。

四张炸弹 < 五张炸弹 < 同花顺 < 六张及以上炸弹 < 四大天王。炸弹先比张数，同张数比较点数；普通牌型须同型同张数。顺子与同花顺、配牌的多个合法点数组合可在界面「作为」中自行选择；服务器按玩家声明验证，历史和语音保留当时的声明。

仍有手牌的玩家顺时针轮流出牌。其余在场玩家都不出后，最后出牌者领出；若其已出完，由仍在场的对家接风，对家也已出完则顺延。头游队伍获胜，搭档二游升3级、三游升2级、末游升1级。双上立即结束，否则第三人出完后结束。两队分别保留级数，下一局打胜方升级后的级数；升至A须再打A，头游搭档不是末游才算打过A。完成后再开一轮从2开始。

下一局自动进贡最大非逢人配牌；单下末游向头游进贡，双下两人各向赢家进贡。较大贡牌给头游，同大按头游起顺时针较近者给头游。单下末游有两张大王，或双下两人合计两张大王则抗贡，头游领出；否则较大贡牌者领出。收贡者手动还2至10的非级牌；无此类牌时还最小的非逢人配牌。还贡界面只显示服务器允许的候选牌，避免误还级牌或在28张牌中找牌。

计分为亲友模式：每位输家分别向两位赢家支付底分×升级数，始终零和；炸弹不额外翻倍。中止不计分、不升级，换人或换座后下局从2重新开始。房间规则采用固定版本 `family-partnership-v1`，不支持的存档版本不能继续操作。牌型术语参考[体育总局的规则发布说明](https://www.sport.gov.cn/n20001280/n20745751/n20767274/c22011669/content.html)，进贡习惯可与地区玩法不同，以上文字与实现一一对应。

## 牌桌与声音

沿用锁定的深青绿台呢、黄铜边线、玉白扑克和本地字体。对家在上，左右为对手，自己手牌在下。桌面27张同屏叠放，手机竖屏自动分排，手机横屏优先整排。最小露出24px牌角，选中抬升16px；支持划选、键盘、完整牌面展开。级牌标「级」，红桃级牌标「配」，标记位于露出的牌角侧。

沿用原创循环BGM，语音期间自动压低音乐，另有发牌、落牌、炸弹和胜负音效。64条离线普通话语音覆盖报牌、组合牌型、四大天王、进贡、还贡、抗贡、接风、余牌、头游及胜负；资源在 `web/public/audio/voice/gd`，可用 `scripts/generate-guandan-audio.ps1` 重建。音乐、语音、音效分别控制开关与音量，偏好沿用另外两种玩法。首次进入、重连、恢复页面、解除暂停均跳过历史播报；暂停、断线、隐藏页面和离桌及时停止声音。

## 验证

- Rust规则测试覆盖双副牌身份和隐私、级牌和王、逢人配、所有连续牌型、炸弹层级、拒绝操作的原子性、接风和已出完玩家的压牌、双上与零和结算、升级和打A、单/双贡及抗贡、还贡兜底、不支持的版本，以及连续40局电脑对战和存档恢复。
- HTTP/WebSocket集成测试覆盖四个座位、越界入座、旁观隐私、事务失败回滚、命令去重、主机重启、三种游戏共存、整局结算、CSV、授权回放和下局升级/进贡。
- 前端36项测试通过，包括掼蛋牌型、配牌解释、事件播报去重、静默重连、离线资源完整性，以及共用音频取消/静音/降低音乐音量等测试。
- 真实浏览器与三个电脑玩家完成三局，经过升级、进贡、手动还贡和结算；开发预览的一组12次操作响应52–95ms，最终内嵌版本的一组12次操作响应24–39ms、页面运行错误为0。第四局还贡候选17张，手动还贡返回200并恢复为27张手牌。这是本机回归数据，不代表所有设备性能。
- 浏览器检查桌面1440×900、竖屏390×844/360×800、横屏844×390/740×360；截图来自真实房间，见 [桌面牌桌](screenshots/guandan-desktop.png)、[手机竖屏](screenshots/guandan-portrait.png)、[手机横屏](screenshots/guandan-landscape.png)、[还贡](screenshots/guandan-tribute.png)、[结算](screenshots/guandan-settlement.png)。实体安卓/iPhone触感、后台和热点仍须真机验收。

## 协议

创建房间：`gameId: "guandan"`；房间容量4。操作仍由 `{type:"game", action:...}` 封装。

```json
{"type":"play","cards":[0,54],"combination":{"kind":"pair","high":3,"len":2,"power":0}}
{"type":"pass"}
{"type":"return","card":4}
```

`combination` 可省略，服务器选择合法且能压过目标的解释；客户端通常显式发送当前选择。服务端不信任客户端声明，按手牌、独立牌ID、级牌和牌型重新验证。合法操作只投影给轮到操作的本人，其他手牌不公开。历史回放仅在完成后向参与者开放，回放按四个座位提供手牌，并清空所有可操作命令。
