# 斗地主与混合房间

大厅「开一桌」可选择四川麻将（4 人）或斗地主（3 人）；列表按游戏类型标识，并支持筛选。同一主机最多保留 32 个开放房间，两种房间共用这个额度，各自拥有独立座位、回合、计时、暂停状态和存档。一个身份可以参加不同房间，但操作只作用于指定房间。

## 斗地主规则 v1

- 一副 54 张牌，三人各 17 张，3 张底牌。轮流不叫/叫 1–3 分，只能叫更高分；3 分立即确定地主，否则三人叫完后最高分者为地主。全不叫时轮换首叫玩家并重新发牌。
- 地主公开收取底牌并先出。点选多张手牌，点击「出牌」提交；「提示」轮换合法候选，「重选」清空选择。服务器重新验证手牌归属、牌型、回合和大小；提示列表不是合法出牌的白名单。
- 单张、对子、三张、三带一、三带二、顺子（至少 5 张）、连对（至少 3 对）、飞机（至少 2 组连续三张，可不带/带单/带对）、四带二、四带两对、炸弹和火箭。
- 连续牌型的主体不含 2 和王。飞机的单翅膀须为不同点数；双翅膀须为不同对子；翅膀不能取自主体点数。四带二的两张可为一对。四带两对须为两个不同对子。
- 同牌型同张数比较主体最大点数；3 最小，2 大于 A，小王、大王依次更大。炸弹压普通牌，火箭压全部；四带二本身不算炸弹。两家连续不出后，上次出牌者重新领出，首家不能不出。
- 地主先出完则地主胜；任一农民先出完则两位农民共同获胜。每位农民与地主单独结算：底分 × 叫分 × 每次炸弹/火箭的 2 倍 × 春天的 2 倍，再应用可选 8/16/32/64 倍封顶。地主总收付为每位农民的两倍，三人净分和为零。
- 地主获胜且两位农民都未出过牌，或农民获胜且地主仅出过一次牌，计春天。没有额外抢地主、明牌、加倍或癞子阶段。

## 叠牌与视听操作

界面使用经典三方牌桌布局：左右为对手、底部为自己、中央显示出牌与地主底牌。桌面和横屏将 20 张手牌叠成一排，窄竖屏分两排，牌角保留点数与花色。点按可切换选择，划过牌角可连续选牌/取消；「展开选牌」提供完整的大牌面。键盘支持左右方向、Home/End 导航，空格/Enter 选牌，Esc 重选。等对手时可以预选，对手出牌不会清空预选；实际出牌由按钮确认并由服务端验证。

顶部声音按钮开启或静音；「更多」可分别调整音乐、出牌语音、动作音效和减少动画。内置 66 条离线中文语音，包含点数报牌、叫分、不出、牌型、余牌、春天与胜负；背景音乐沿用原创曲目。新动作依服务端公开事件播放，首次进入、重连、解除暂停及切回页面不会倒播历史。网页隐藏或离桌停止声音，语音期间音乐自动降低音量。

炸弹扩散、火箭上升、飞机掠过、春天和胜负印章均不拦截点击；减少动画时保留静态文字。回放继续使用同一套扑克牌面，不播放实时声音。

## 托管与恢复

空座可加电脑。电脑只根据自己的手牌、公开叫分与出牌决定行动；不会读取其他人的暗牌。真人断线 60 秒后临时托管，原浏览器重连后取回控制。启用计时时，在线玩家超时也由电脑代操作。服务重启后进行中的房间暂停，房主点击继续；两类房间的恢复互相独立。

结算写入累计分、历史、逐笔账目和逐步回放，支持 JSON / CSV 导出。进行中只返回当前玩家手牌，叫分阶段隐藏底牌；历史回放只允许已结束局的参与者、房主或主机管理员读取全部手牌。中止未结算的斗地主局不计分。

## 协议

`GET /api/v1/games` 返回两种定义。创建房间请求的 `gameId` 可为 `sichuan-blood-battle` 或 `doudizhu`，省略仍默认麻将；列表新增 `capacity`。`seats` 和 `round_players` 长度随游戏变化，不应假定固定为 4。

斗地主共用 `/rooms/{id}/command`、版本校验、命令 ID 去重和 WebSocket 房间订阅。游戏命令包在 `{ "type": "game", "action": ... }` 中：

```json
{ "type": "bid", "score": 3 }
{ "type": "play", "cards": [0, 1] }
{ "type": "pass" }
```

`cards` 是唯一的牌 ID：0–51 按 3、4、…、A、2 每点数 4 张排列，花色依次黑桃、红桃、梅花、方块；52 小王、53 大王。不可重复提交同一 ID。斗地主 `game` 投影包含 `phase`（`bidding`/`playing`/`finished`/`aborted`）、`own_hand`、`players[].hand_count`、`bottom`、`bids`、`landlord`、`multiplier`、`last_play`、`legal_actions`、`events`、`ledger` 和 `winners`。`legal_actions` 最多提供 64 种出牌建议，客户端可提交其他合法组合。

历史和回放顶层 `gameId` 用于选择正确的显示组件，规则版本为 `family-bidding-v1`。原有麻将状态和回放的 JSON 结构继续兼容，房间层通过 `RoomGame` 分派引擎。

