# 四川麻将界面与工程交接

最新覆盖规范：本轮手机横屏完整手牌、自己的碰杠、新摸牌、声音和动作反馈以 [gameplay-refinement.md](gameplay-refinement.md) 为准，以下旧版滚动手牌说明只保留修订历史。

Every screen must read as the same product if placed side by side.

## 流程与状态
- 初始读取主机与会话。未建立身份时在开桌或入座前输入昵称；身份凭据存 localStorage，不按昵称恢复。
- 大厅以左侧紧凑导航、顶栏主机连接信息、右侧开桌入口、横向房间列表组成。无房间时说明“还没有牌桌”，开桌是唯一主操作。
- 开桌表单分为名称与昵称、计分、计时三个段落。默认遵循已批准计划，不换三张；提交等待服务器确认再转房间。
- 候场显示真实四座、机器人补位、准备状态。房主控制开局与暂停，其他玩家准备。未满座可加电脑。邀请对话框给出可选网络地址、链接与本地 QR SVG。
- 牌桌以自己手牌在底部、三名对手在周围、中央牌河构成。行动权用黄铜线标明，已胡与掉线同时有文字状态。显示牌墙、轮次、缺门、公开副露、逐笔账目。服务器 legal_actions 决定按钮。
- 点牌只选择，再点击“打出”确认；支持键盘 Tab/Enter/Space。定缺三个明确按钮。胡/杠/碰/过出现在手牌上方，不自动代用户确认。
- 已结束显示结算、继续与历史入口。中止有明确确认。历史列表按房间、日期、玩家过滤；回放可选视角、进度、单步和播放，导出 CSV/JSON。
- WebSocket 丢线保留最近画面，禁用提交并显示重连提示，退避重连。旧版本拒绝后刷新，不乐观改牌。身份失效明确要求重新加入。
- URL 保存 room/invite，刷新恢复同一房间；大厅不离开座位，离开通过单独动作确认。

## 组件约束
|组件|数据与行为|边界状态|
|---|---|---|
|RoomList|RoomSummary 列表、真实人数、状态、入座按钮|加载文本、无房间空态、连接错误重试|
|RoomForm|RoomConfig，校验正整数底分；其余合法枚举|提交禁用、服务器错误保留输入|
|InviteDialog|地址列表、room ID 与 invite，QRCodeSVG|复制回退选择文本、无地址提示检查网络|
|MahjongTile|0..26 万条筒，SVG 圆点/竹条/万数字，selected/disabled/back|中文 aria-label，手牌最小48x64，牌河纯展示缩小|
|Seat|真实名字、头像、分数、当前行动、已胡、定缺|空座“等待入座”，机器人标识，掉线状态文字|
|ActionBar|legal_actions 映射，并发送原对象|请求中禁用，非法响应显示错误并重新取状态|
|Ledger|ScoreEntry 与玩家名|无账目解释，长列表滚动，正负数不只靠颜色|
|Replay|完成局的 manifest/frames|无回放说明，结束停止播放，视角切换不改变进度|

手机竖屏缩紧牌桌外围，手牌以可横向滚动的至少48px牌面呈现，行动区固定在手牌旁并包含安全区域。横屏短高度时缩小桌面，不缩小操作按钮。桌面最大内容宽度 1440px。昵称可截断但 title 提供完整文本。大字切换提高正文与按钮字体。错误 aria-live=polite，阻断错误 role=alert，对话框 Escape 返回触发器。

## Pre-flight
设计稿约束检查：一个强调色、一套圆角、一个图标库、一组字体；禁止项0；导航3项；每段表单不超过4字段。布局分别为窄导航、规则列表、围桌空间、数据表；没有重复营销卡。所有交互均定义加载/错误/禁用与键盘，离线恢复路径明确。对比度需实现脚本再核验，真机触摸和屏幕阅读器仍需验收，不能仅按规格声称通过。

评分（规格，非实测）：独特性3、层级3、一致性4、无障碍3、状态覆盖3、文案3、克制4、动效动机3，总26/32。修订：竖屏手牌由自动缩小改为横向滚动，确保可触控；用真实空态取代演示牌桌，避免虚构状态。

## 工程交接
目标代理：react-vite-tailwind-engineer（本项目 frontend 工程职责）。React + TypeScript + Vite，Radix Dialog、Motion、Lucide、qrcode.react，本地 Fontsource 思源同源字体。Implement exactly this spec. Theme the design system with our locked tokens; do NOT redesign or re-implement its components.

接口隔离于 web/src/api.ts，遵循根代理定义的 /api/v1 和 /ws/v1。验收包括 TypeScript/build、房间创建与入座、候场准备/机器人、服务器合法动作映射、端口访问、键盘与360px竖屏/桌面屏布局。所有计分与对局状态都由服务器提供；不可在前端模拟假比分或读取隐藏牌。

## 本轮工程交接：真实牌面与长辈易用性

目标仍为 frontend 工程代理。实现本文件与 DESIGN.md 的修订，不改游戏规则、鉴权或 API；不新造设计系统。

1. 重画全部条筒 SVG，逐张传统排列；一条明确鸟形，二至九条为有竹节的纵向或传统斜向竹段。筒纹不可看成空心占位符。27张牌在「认牌与玩法」帮助中按万、条、筒排列，配中文牌名，手机可纵向浏览。
2. 桌面保持围桌关系，手机压缩对手区域与无用留白。手牌与行动区组成稳定的操作区，360px竖屏和844×390横屏均可完成全部动作。不得通过缩小点击区来塞满13张牌。
3. 操作区持续回答当前状态：请选择定缺 / 轮到你，请选一张牌 / 已选三条，点打出 / 等待某某出牌 / 某某打出五筒，请选择 / 本局已胡，可继续看牌 / 连接中，暂不能操作。选牌文字和大号牌预览结合，不只靠抬升或颜色。随服务器状态变更清除失效选择。
4. 定缺说明「此门的牌必须先打完，才能胡牌」，显示本人三门数量（不读取他人手牌）。定缺按钮大且带花色示例牌。碰杠胡用完整中文文字；有合法胡牌时点击过先确认一次放弃，其他普通过不增加确认。
5. 大厅主操作为「开一桌」，已有房间可清楚「入座」。候场明确还差几人、自己是否准备，电脑补位与开始对局先后清楚。分享入口「邀请亲友」、账本入口「分数」、帮助入口「玩法」、设置入口「设置」，不依赖猜图标。
6. 离开/中止等高影响动作收进二级设置并保留明确确认。大字、静音、减少动画为通俗名称、持久化。避免把调试术语、接口版本和服务器内部状态显示在主游戏流程。
7. 验收：全27张牌展示截图；桌面1440×1000、竖屏390×844和360×800、横屏844×390截图；大字模式、选牌确认、定缺、合法动作、键盘、弹窗焦点与滚动、不产生整页横向溢出。真实服务器完成一局，回放/账目一致。记录仅属于浏览器模拟视口的范围，不冒充长辈试用或实体手机验收。

大厅视觉复核补充：不使用半屏宣传 hero、旋转牌阵叠加圆形徽章或装饰口号。标题直接为聚会大厅/四川麻将，简短说明同一 Wi-Fi 扫码入座，唯一主按钮「开一桌」，实际房间列表紧随其后。未登录不能把未知房间数画成 0 桌；显示登录说明。可保留小型真实牌面作为游戏识别标记，尺寸不能把房间列表挤出首屏。空列表不用重复同等视觉权重的开桌按钮。

修订前检查：保持一套字型、圆角、强调色；新增三色仅为传统牌纹。导航不超过五项、操作按当前阶段渐进显示；加载、断线、过期动作沿用既有真实状态。修订理由：取消抽象竹节与机械点阵，提升熟悉度；增大手牌和明确动词，降低记忆负担。规格自评：独特性3、层级4、一致性4、无障碍3、状态覆盖3、文案4、克制4、动效3，总28/32。实际视觉和触控结果待实现后检查。
