# 全桌行为反馈与四人结算确认

继承 DESIGN.md 的精致茶馆设计。以玉白/黄铜书法印记、轻扫光和数字位移突出真实行为，禁止金币雨、满屏粒子、反复闪烁或遮住出牌按钮。

## 对局反馈
- 所有四个客户端处理同一公开事件流，任何玩家的碰、暗杠、直杠、补杠成立、胡、自摸、抢杠胡均显示操作者姓名与大号行为印记。中心短动画配对应座位亮边；暗杠不展示隐藏牌面，补杠申请不作为成立播放。
- 一炮多响不得丢失赢家。按事件顺序排队或合并同一次响应的多胡；动画不阻塞规则推进，不能只取最后一个事件。刷新/重连只建立基线，不重播过去整局；同一事件不会重复播。
- 新账目全部可追溯：按操作聚合四家分数增量，同时显示谁付给谁、原因、金额。飘分有正负号、姓名与文本，不仅依赖颜色。与本人无关的收付也能看到。多个收付不得因同一帧到达而丢失。
- 反馈短暂呈现后保留最近收付入口/可读记录。减少动画时保留文字与分数，静音不影响视觉。小横屏不覆盖手牌、行动按钮、一级横屏/邀请。

## 每局结算
- 结束自动展示本局结算，突出本人本局变化；四人卡片列姓名、本局收入/支出/净变化与累计分数，支持查看每人的逐笔原因、付款/收款对象。全局净分守恒可见，无收付显示0分及无收付说明。中止局保留已发生账目并标记中止。
- 显示四人确认状态（电脑自动确认，真人不会因掉线或托管自动确认）。本人的主按钮“确认本局分数”，确认后显示“已确认，等待其他人”。可关闭查看牌桌并重新打开，但关闭不能代替确认。
- 四人全部确认后才提供房主“开始下一局”；确认视为本人对下一局准备，保留原有房主开始动作，不自动强制开局。不额外要求已确认者再按一次准备。
- 未全部确认时服务端禁止下一局与座位变更；掉线等待重连，仍可由现有房主恢复身份。确认状态持久化，旧局确认不能误确认下一局。

## 前后端约定
RoomView新增 `settlement: null | { round: number; acknowledged: boolean[4]; allAcknowledged: boolean }`，仅该局仍在座参与者可见。现有game.ledger提供逐笔账目，game.players[i].score为本局净变化，room.seats[i].score为累计。根代理实现后端。
命令 `{ type: 'confirmSettlement', round: room.round }`，必须绑定当前局。服务器允许本局确认的较旧版本并合并四人确认（独立幂等操作）；其它操作继续拒绝旧版本。确认自带玩家凭据，不能代其他人确认。
